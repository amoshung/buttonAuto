# 🤖 AI 工程助理
Windows 桌面小工具，代替你盯著 Kiro / Antigravity 的 AI 代理：用虛擬點擊（UI Automation，不動實體滑鼠）按按鈕，並在它判斷出的聊天輸入框輸入文字。完整規劃見 `docs/superpowers/plans/2026-11-13-ai-engineering-assistant.md`。

- **只操作勾選的視窗**：「工作階段」分頁列出每個 Kiro / Antigravity 視窗開的專案與完整路徑（從視窗標題與 IDE 的 workspaceStorage 對應），新偵測到的視窗預設不勾選。每次動手前都會再確認視窗還在、專案沒變、仍是勾選狀態。
- **退回基本按鈕精靈**：原本的「UIA 按鈕」（也只點勾選的視窗）與「圖片比對」（會移動滑鼠）模式保留在「基本按鈕精靈」分頁。

| 模式 | 做法 | 會動滑鼠嗎 |
|---|---|---|
| **AI 工程助理** | OCR 模型判讀 IDE 狀態，決策模型決定要點按鈕、回覆「繼續」、理解後回覆，或交給你決定 | 不會（打字時才短暫切換鍵盤焦點） |
| 基本按鈕精靈・UIA 按鈕 | 依名稱找按鈕（如 `Allow`、`Always allow`、`Submit`）並直接 Invoke | 不會 |
| 基本按鈕精靈・圖片比對 | OpenCV 比對 `targets/` 截圖，命中後瞬移點擊再把游標移回 | 會 |
## 工作階段的目標與進度（P1：只觀察、只建議）
- 每個工作階段在 `sessions/<App>__<專案>/` 有自己的 `state.json`、`progress.md`、`history.jsonl`（已列入 `.gitignore`）。
- 在「工作階段」分頁按「目標／建議」：輸入目標；進行中的專案可先送出「詢問最終目標」，代理回答後助理會整理出來，由你採用或修改。
- 代理停下來時，驅動器會依目標與進度寫出建議的下一步（要求證據、故意弄壞、功能分支 commit、請代理自己決定技術做法等）。**不會自動送出**，送出要你在對話框按「送出這則訊息」。
- 每次操作 IDE 之前都會先讀該工作階段的進度，並把打算做的事寫進 `history.jsonl`。
- 每日摘要：預設 18:00 產生 `reports/daily-YYYY-MM-DD.md`，也可在「AI 設定」分頁按「立即產生」。

## 自動駕駛（P2）
每個工作階段依序走過四個階段，對話框上方的「🚦 階段與自動駕駛」會顯示目前在哪一段：

1. **確認目標**：由你訂定；進行中的專案可先請代理說明最終目標。
2. **討論驗收 spec**：助理請代理提出可檢查的驗收條件（每條含驗證方式與測試），自動審查、不夠具體就請代理修改（最多 3 輪）。定稿後**等你按「確認驗收 spec」**才開始實作。
3. **實作與查核證據**：代理說完成時，助理改用固定格式要求測試報告（完整測試輸出、逐條對照、故意弄壞、功能分支 commit，不可 push）。助理在本機唯讀查核：commit 是否存在、是否在功能分支、工作目錄是否乾淨、改過的檔案有沒有空殼跡象（TODO、只有 pass、`assert True`、被略過的測試等）。有問題就把具體缺口回給代理；連續 3 次要不到合格證據就暫停並交給你。
4. **已達成目標**：全部驗收條件查核通過後停止推進、關閉自動駕駛並通知你。

自動送出與代按 Allow 需要同時符合：「AI 設定」的全域觀察模式**關閉**，且該工作階段的「自動駕駛」**打開**。其他保護：
- 代理工作中、在等 Allow、或你正在操作電腦時不送；每個工作階段每小時最多 12 次。
- 所有 `git push`、強制推送、刪除類指令都交給你。
- 代理原地打轉或同一個對話送出超過 30 則時，開新對話並用進度摘要接續。
- 測試報告存在 `sessions/<App>__<專案>/reports/`（遠端專案改為貼在聊天裡，只能依報告內容判斷）。

## 🚀 快速開始
1. 雙擊 **`run.bat`**（缺套件時會自動安裝），或執行 `pip install -r requirements.txt` 後 `python main.py`。
2. 選擇運作模式，按 **「▶ 啟動 (F8)」** 或鍵盤 **`F8`**。

Electron 類 IDE 在第一次被 UIA 查詢後才開放無障礙樹，剛啟動時可能要等下一輪才看得到按鈕。

## AI 工程助理的判斷流程
每一輪、每個監看視窗：
1. 背景截圖（`PrintWindow`，被其他視窗蓋住也能截；最小化的視窗會跳過）＋ UIA 讀取聊天面板文字、按鈕與輸入框。
2. 畫面沒變化就不呼叫模型。
3. OCR 判讀模型（預設 gemma-4-31b）輸出狀態 JSON；找得到聊天面板時只送面板裁切圖，再用 UIA 讀到的原文校正指令與選項文字（working / waiting_approval / asking_choice / waiting_input / error / done / idle）。
4. 危險指令規則（`config.json` 的 `deny_patterns`）命中 → 交給你決定。
5. 決策模型回傳動作與風險機率；風險高於門檻或信心度不足 → 交給你決定。
6. 「理解後回覆」：判斷/回覆模型（預設 gemma-4-31b）看截圖擬回覆 → 再經規則與決策模型檢查風險與切題程度才送出。
7. 按鈕一律用 UIA Invoke 點擊，不使用模型給的座標。打字前會等你閒置（預設 3 秒），輸入框有草稿時不輸入，輸入完把焦點切回原本的視窗。

需要你決定的視窗會列在「工作階段」分頁下方並閃爍工作列，輪巡時跳過，直到畫面有變化或你按「恢復輪巡」。

**預設開啟「觀察模式」**：只記錄 AI 打算做什麼，不實際操作。看過日誌（`automation.log`）確認判斷合理後再關閉。

## 模型分工與決策方式
| 角色 | 預設模型 | 用途 |
|---|---|---|
| OCR 判讀 | 中鋼主權 AI `gemma-4-31b` | 詳細讀取畫面文字，判斷代理狀態 |
| 判斷/回覆 | 中鋼主權 AI `gemma-4-31b` | 快速決策、擬回覆 |
| 決策（選用） | Decision-1 | 取代判斷模型做決策，機率較準，但依用量計費 |

「API 設定」分頁的「決策方式」可選：
- **主權 AI 判斷模型（免費，預設）**：只需要中鋼主權 AI 的金鑰。
- **Decision-1（付費）**：另需 LiteLLM 金鑰。

一般 LLM 自己報的信心度不像 Decision-1 是校準過的機率，常出現 1.0、0.0 這種極端值。用免費模式時建議維持觀察模式久一點，再決定門檻。

## 選項題
代理請你從幾個選項中選一個時（例如「回覆 1~4」或 A/B/C/D 按鈕），決策模型會依 OCR 讀到的選項選出最佳的一個，並逐一評估每個選項的風險：
- 選項是按鈕 → 用 UIA 點那個按鈕；選項是文字 → 在輸入框打選項代號（沒有代號就打選項內容）。
- 最佳選項的信心度低於「選項題最低信心度」（預設 0.5），或該選項風險高於門檻 → 交給你決定。
- 可在「AI 代理」分頁關閉「選項題由決策模型選出最佳選項」。

## OCR 模型比較（實測）
| 模型 | 清楚的大字（14 題） | 縮小的指令完全正確 | 中文選項完全正確 | 中位延遲 |
|---|---|---|---|---|
| **gemma-4-31b（預設）** | 14/14 | 6/12 | 2/4 | 2.2 秒 |
| qwen-vl | 13/14 | 3/12 | 3/4 | 3.1 秒 |
| moa | 7/7 | 4/8 | 2/4 | 5.8 秒 |
| muse-glimmer | 12/14 | 2/4 | 3/4 | 20 秒 |

小字指令每個模型都會抄錯符號，所以程式會用 UIA 讀到的原文校正；UIA 讀不到時才完全依賴 OCR。

## API 設定
「API 設定」分頁可輸入兩組服務的 Base URL、模型與金鑰，存在 `secrets.local.json`（已列入 `.gitignore`）。金鑰來源可選：
- **從檔案讀取**（預設）：讀取 `key_file` 指定的檔案，檔案內容只放金鑰。
- **手動輸入**：直接在面板輸入。

## 圖片比對模式的其他功能
- 多螢幕、多掃描區域框、滑鼠可穿透的綠色提示框。
- 面板內截圖新增目標按鈕，自動排除面板本身的範圍。
- Per-Monitor 高 DPI 感知。

## 像素辦公室（網頁儀表板）

主視窗標題列的「🌐」會打開像素辦公室：每個開著的 IDE 視窗是一位同事，狀態用動作表示（打字＝工作中、舉手＝需要你、去茶水間＝閒置、坐著暫停＝模式關閉）。點同事可以看目標與進度、切換模式、代按代理在等的按鈕、打字傳話給代理、請助理開新對話接續。右上角「全部暫停」等同 F8。舊的清單式畫面在 `/classic/`。

- 介面原始碼在 `pixeloffice/`（Next.js，改自 [amoshung/pixeloffice_y6p2](https://github.com/amoshung/pixeloffice_y6p2)），建置結果已放在 `web/pixel/`，執行助理不需要 Node。
- 修改介面後重新建置：`cd pixeloffice && npm install && npm run build`（會更新 `web/pixel/`）。
- 資料與動作由 `office_bridge.py` 轉接：只綁 127.0.0.1、需要存取碼；網頁上的按鈕只接受代理當下列出的選項，實際操作與桌面版走同一套規則。
