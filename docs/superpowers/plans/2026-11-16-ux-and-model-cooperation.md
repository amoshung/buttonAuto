# AI 工程助理：介面重新設計與模型協調改善

> 狀態：C1～C3 完成（2026-11-16）；C4 驗收：Kiro 沙盒已達成（16/16 核心項目查核通過），Antigravity 沙盒剩 1 條

## 問題
1. **不會自動做事**：代按 Allow 時讓 Decision-1 從一堆按鈕裡挑一個，機率分散在 Allow／Always allow／Deny，最高只有 0.3～0.4，被判定「信心度不足」交給使用者。風險 0.5 左右的一般指令也直接交給使用者。
2. **開關太多**：要按「啟動」、勾選視窗、在對話框開「自動駕駛」、在「AI 設定」關「觀察模式」四件事都做到才會動。
3. **助理會操作自己的對話**：勾選了開著助理專案的 Kiro 視窗後，助理替使用者代按了寫檔確認，導致修改被取消。

## B. 模型協調
| # | 改善 | 做法 |
|---|---|---|
| B1 | 代按 Allow 改成兩個是非題 | Decision-1 只回答「為了目標且在範圍內？」「會不會難以復原？」；按哪個鈕由程式固定選「只允許這一次」 |
| B2 | 分工 | gemma：讀畫面、寫訊息、逐行審查指令；Decision-1：是非把關；本機唯讀查核：事實的最終依據 |
| B3 | 灰色地帶找第二意見 | 風險介於 0.3～0.7 時請 gemma 逐行審查，兩者都說安全才代按；> 0.7 或意見不同才交給使用者 |
| B4 | 不看最高信心度 | 一般動作改看「需要人類決定」本身的機率是否偏高 |
| B5 | 決策附上目標與範圍 | 狀態文字包含目標與允許範圍（例如只能動 `ai_assistant_sandbox`） |
| B6 | 記錄與校正 | 每日摘要列出「交給你但其實可自動」「自動了但你不同意」次數，作為調門檻依據 |

## A. 介面
| # | 改善 |
|---|---|
| A1 | 每個視窗一個模式選單：關閉／只建議／自動駕駛；移除勾選框、對話框自動駕駛開關、全域觀察模式 |
| A2 | 開啟就自動運作；主按鈕改為「全部暫停／繼續」（F8） |
| A3 | 每列狀態用白話寫出下一步 |
| A4 | 對話框：階段進度條＋一顆主要按鈕；計畫文件與報告資料夾收進「進階」 |
| A5 | 「需要你決定」放主畫面最上方，每項附可直接處理的按鈕 |
| A6 | 專案路徑包含助理安裝資料夾的視窗預設關閉；切自動駕駛前再確認 |
